## 5. 容量验收

| 场景 | Word 目标 | 实测 | 判定 |
| --- | --- | --- | --- |
| WebSocket | 500 连接 | 500/500 保持 60s，0 失败 | **PASS** |
| 稳定流 | 200 msg/s×5min，P95<300ms | 197.76 msg/s，59,129 条，P95 200ms，0 失败 | **PASS** |
| 稳定流排空 | Outbox/NATS 追平 | 停压 T+0～60s Outbox 均 0；NATS 0/0 | **PASS** |
| 突发流 | 1000 msg/s×30s | 3 API：411.22 msg/s，P95 2.4s，0 失败 | **FAIL** |
| 财务 | 100 QPS，P95<500ms | 100.08 QPS，P95 130ms | **PASS** |
| 20% LLM 超时 | 降级不断链 | 完整回复 P95 1.2s，0 错误 | **PASS** |

Outbox relay 已从逐条发布/逐条提交改为批量领取、有界并发发布和单事务批量确认。200 msg/s 的端到端旧缺口已经关闭。1000 msg/s 从单 API 239.14 msg/s且 6 次失败，提升到三 API 411.22 msg/s且零失败，扩容方向有效但目标仍未达到。

数据库长时间中断、多实例网络分区和告警联动尚未作为完整生产混沌测试执行。

## 7. 安全、成本与工程卫生

- `.env` 被 `.gitignore` 排除；跟踪文件不包含真实 key。
- 全量回归与压测显式使用 Mock LLM；隔离压测库无 LLM usage 新增，真实 DeepSeek 新增费用为 0。
- 多租户越权、财务脱敏、工具 allowlist、高风险确认和幂等冲突均有自动化测试。
- 财务查询统一记录成功、失败或拒绝审计；LLM 不拥有直接工具执行权。
- Compose 默认连接池由每实例 20+20 调整为 8+4，完整拓扑理论预算约 60，小于 PostgreSQL 默认 100。
- Outbox 参数、压测多 API endpoint 和应用队列指标均已配置化并写入 `.env.example`。

## 9. 未完成边界

主要未完成项只有 1000 msg/s 的指定容量证明。下一步应在独占 8C16G 中使用真实 Ingress/LB、3+ API、PgBouncer 和合理 worker 阶梯重跑，实际接收约 30,000 条并证明无丢失与可排空后再改判。

专用 embedding、大规模人工盲评、批量死信治理和生产级长时间混沌测试属于进一步工程化，不影响本次面试 Demo 的功能验收，但不能宣称已经具备完整生产 SLA。
