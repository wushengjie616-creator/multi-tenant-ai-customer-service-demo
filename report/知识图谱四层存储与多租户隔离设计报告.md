> 状态：定稿

## 1. 结论摘要（TL;DR）

面向多租户高并发客服场景，知识图谱的四个逻辑层各落一张 PostgreSQL 表，以 **PG 为事实源（system-of-record）**、**Qdrant 为可重建加速器**、**jsonl 仅作离线中间产物**：

| 逻辑层 | 物理表 | 职责 |
|---|---|---|
| 原文 | `knowledge_documents` | 不可变原始文本 + 内容哈希，审计/溯源/重跑 |
| ES 文档 | `knowledge_es_documents` | 长文本 / 半结构化详情，长文本语义检索 |
| 图节点 | `knowledge_graph_nodes` | 类型化实体（class/teacher/campus/…） |
| 图边 | `knowledge_graph_edges` | 实体关系（teaches/located_at/…） |

**多租户隔离靠三条硬约束落地**：`tenant_id` 是每张表第一列 + 外键级联删除 + 所有查询与复合索引都以 `tenant_id` 为前缀。任何一层都不存在"裸查全库"的路径。

## 2. 存储选型：为什么这样分

### 2.1 jsonl 为什么不能当事实源

早期方案倾向把节点/边写进 jsonl 文件。否决理由：

1. **无租户隔离**：jsonl 是平面文件，租户隔离只能靠文件名/目录约定，无法用 SQL `WHERE tenant_id = ?` 硬保证，多租户下是数据泄漏面。
2. **无反向索引**：查"A3 有哪些老师教"需要全表扫 jsonl；关系型里一条 `to_node_id` 复合索引即可。
3. **无事务**：同文档的四层替换必须是原子的，jsonl 做不到 delete-then-insert 的原子幂等。

**jsonl 保留的正确用途**：离线抽取的中间产物、审计快照、可重跑输出——是"过程痕迹"，不是"在线可查询的事实源"。

### 2.2 为什么 PG 当事实源

- **事务性**：`replace_document` 在一个事务内完成四层 delete-then-insert，同 `document_id` 重复导入覆盖旧图、零孤儿。
- **租户隔离**：`tenant_id` 外键 + 复合索引，天然满足多租户硬隔离。
- **JSONB 弹性**：`attributes`/`aliases`/`body` 用 JSONB，属性 schema 演进不必改表，同时保留索引能力。

### 2.3 Qdrant 的定位（关键取舍）

Qdrant 仍负责 **chunk/向量召回**（既有 `education_knowledge` 集合不动），**不替代**图/ES。它是"可重建加速器"：任何时刻都能从 PG 事实源重建，丢了也不丢事实。四层存储是**新增召回层**，不是换掉向量召回。

## 3. 四表 schema

### 3.1 通用约定

- 每表 `id` 为 UUID 主键；**`tenant_id`（UUID）为第二列、业务上的第一过滤列**，外键 `tenants.id ON DELETE CASCADE`。
- 时间戳 `created_at` / `updated_at` 由 DB 默认 `now()`。
- JSONB 列带 `server_default`（`'{}'::jsonb` / `'[]'::jsonb`），避免空值歧义。

### 3.2 列与索引一览

**`knowledge_documents`（原文层）**

| 列 | 类型 | 说明 |
|---|---|---|
| tenant_id | UUID | 租户，FK CASCADE |
| document_id | varchar(128) | 文档业务 id |
| title / source / format | varchar | 标题 / 来源 / 格式（markdown） |
| content | text | 不可变原始全文 |
| content_hash | varchar(64) | sha256，去重与变更检测 |
| version | int | 版本号 |
| visibility / review_status | varchar(32) | public / approved |
| effective_from / effective_until | varchar(64) | 生效窗口（可空） |

索引：`UNIQUE(tenant_id, document_id, version)` + `ix_knowledge_documents_tenant_id` + `ix_knowledge_documents_document_id`。

**`knowledge_es_documents`（ES 文档层）**

| 列 | 类型 | 说明 |
|---|---|---|
| tenant_id | UUID | 租户 |
| es_doc_id | varchar(160) | `es:{document_id}:{version}` |
| document_id | varchar(128) | 关联原文 |
| kind | varchar(32) | document（预留 section 等） |
| title | varchar(255) | 标题 |
| body | jsonb | 结构化元数据（source/version/content_hash） |
| body_text | text | 长文本正文，长文本语义检索用 |

索引：`UNIQUE(tenant_id, es_doc_id)` + `ix_knowledge_es_documents_tenant_id` + `ix_knowledge_es_documents_document_id`。

**`knowledge_graph_nodes`（节点层）**

| 列 | 类型 | 说明 |
|---|---|---|
| tenant_id | UUID | 租户 |
| node_id | varchar(160) | 稳定节点 id（`{type}:{uuid5hex12}`） |
| type | varchar(32) | 枚举：class/teacher/campus/policy/order/invoice/customer/activity/institution |
| name | varchar(255) | 归一化实体名 |
| document_id | varchar(128) | 来源文档 |
| aliases | jsonb | 别名数组（如 `["A3"]`） |
| attributes | jsonb | 属性对象（编码/价格/课时数/适合年级…） |
| es_doc_id | varchar(160) | 回链 ES 详情（可空） |
| schema_version | varchar(16) | v1 |
| effective_from / effective_until | varchar(64) | 生效窗口（可空） |

索引：`UNIQUE(tenant_id, node_id)` + `ix_knowledge_graph_nodes_tenant_id` + `ix_knowledge_nodes_tenant_type`（租户+类型）+ `ix_knowledge_nodes_tenant_doc`（租户+文档）。

**`knowledge_graph_edges`（边层）**

| 列 | 类型 | 说明 |
|---|---|---|
| tenant_id | UUID | 租户 |
| edge_id | varchar(160) | 稳定边 id |
| type | varchar(32) | 枚举：teaches/located_at/governed_by/has_order/invoices/enrolls/applies_to/recommends |
| from_node_id / to_node_id | varchar(160) | 有向边两端 |
| document_id | varchar(128) | 来源文档 |
| schema_version | varchar(16) | v1 |

索引：`UNIQUE(tenant_id, edge_id)` + `ix_knowledge_graph_edges_tenant_id` + `ix_knowledge_edges_tenant_from`（租户+from+type）+ `ix_knowledge_edges_tenant_to`（租户+to+type，反向邻接）+ `ix_knowledge_edges_tenant_doc`（租户+文档）。

> 正向（from）与反向（to）双邻接索引，保证"X 教什么"和"什么由 X 教"两个方向都能走索引，不做全表扫。

## 4. 确定性抽取器（无 LLM 依赖的基线）

### 4.1 三层定位

1. **确定性抽取器**（`graph_extraction.py`）：regex 可证的 class / teacher / campus 三类，覆盖"课程目录"这类结构化源，**零 LLM 成本、可复现**。
2. **LLM 抽取器（预留）**：policy / order / invoice / customer / activity / institution 六类需语义判断，后续补位。
3. **校验层**（`validate_graph`）：两类输出都过**同一层**，枚举锁定 + 悬空边丢弃，不信任任何原始输出。

### 4.2 抽取规则要点

- **实体 = 具名实体**：`可选校区 / 本校区` 等泛称不进节点（负规则 blocklist）。
- **不填臆造值**：文档没写的属性缺省为 null（母本 §6.1）。
- **教师/校区跨章节去重**：同文档内同名校区/教师只建一个节点，多班共边。

### 4.3 稳定 id（母本 §9 实体消歧基础）

```
node_id = "{type}:{uuid5(NAMESPACE_URL, tenant_id + ':' + type + ':' + 归一化名).hex[:12]}"
edge_id = "{type}:{uuid5(NAMESPACE_URL, tenant_id + ':' + type + ':' + from + ':' + to).hex[:12]}"
```

带来的两个性质：

- **跨文档对齐**：同租户+同类型+同名 → 同 id，实体跨文档天然合并。
- **租户天然隔离**：tenant_id 参与哈希，不同租户同名实体 id 必不同（单测显式断言）。

## 5. 多租户隔离设计

| 机制 | 落点 |
|---|---|
| **物理隔离锚点** | 每表 `tenant_id` 第一过滤列，`FK tenants.id ON DELETE CASCADE` |
| **查询硬过滤** | 读写入口一律 `WHERE tenant_id = ?`，无裸查路径 |
| **索引前缀** | 所有复合索引以 `tenant_id` 打头，租户内查询命中索引 |
| **级联清理** | 租户删除级联清空四层，不留孤儿 |
| **API 层** | `GET /knowledge/graph` 从 `get_current_user` 取 tenant，不信任请求体传租户 |

集成测试覆盖：租户 A 导入后，租户 B 的只读视图返回空（`tests/integration/test_graph_store.py::test_graph_is_tenant_isolated`）。

## 6. 检索定位（第四条召回路径，当前留空）

现有 `answer_question` 三路召回（向量 / 实体 / 文本）不变。知识图谱是**第四条召回路径**，逻辑如下（本报告只描述、不接线）：

1. 问题过意图识别与实体识别，落到结构化条件（课程编码/年级/校区/老师…）。
2. 结构化条件在图节点层**精确命中**（`tenant_id` + `type` + `attributes` JSONB 查询），再沿边做一跳邻接扩展（如命中课程 → 反查 `teaches` 老师 → `located_at` 校区）。
3. 图命中结果与向量召回去重合并，进证据门（`MIN_SCORE`）统一裁决。

**当前状态**：存储 + 抽取 + 只读视图已落地并验证；检索接线**刻意留空**，按约定不实现，仅保留此定位说明。
