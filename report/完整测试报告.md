## 1. 验收结论

**可作为面试 Demo 正式交付；核心功能和 200 msg/s 端到端目标通过，1000 msg/s 生产容量仍未证明。**

- 单元/集成 238 个、E2E 10 个全部通过，核心覆盖率 76.45%。
- 50 条路由评测与 5 条真实 Qdrant RAG 金标全部通过。
- 500 WebSocket、200 msg/s×5min、100 QPS 财务、20% LLM 超时降级均通过。
- 1000 msg/s×30s 在 2C4G 上：三 API 达到 411.22 msg/s、0 失败，仍未达到目标。
- 原生 LLM token 流式、RAG 多轮指代改写、转人工 LLM 摘要、自然语言提醒候选解析均已实现并有测试。

## 6. 容量测试

| 场景 | 目标 | 实测 | 延迟 | 错误 | 判定 |
| --- | --- | --- | --- | ---: | --- |
| WebSocket | 500 长连接 | 500/500，60s | 建连 P95 250ms | 0% | **PASS** |
| 稳定流 | 200 msg/s×5min，P95<300ms | 59,129 条，197.76 msg/s | P50 50ms / P95 200ms / P99 270ms | 0% | **PASS** |
| 稳定流排空 | Outbox/NATS 追平 | 停压 T+0～60s Outbox 均为 0；NATS 为 0/0 | — | — | **PASS** |
| 突发 | 1000 msg/s×30s | 三 API：11,980 条，411.22 msg/s | P50 1.1s / P95 2.4s / P99 3.3s | 0% | **FAIL** |
| 财务 | 100 QPS，P95<500ms | 100.08 QPS，2,908 次 | P95 130ms | 0% | **PASS** |
| 20% LLM 超时 | 降级不断链 | 124 完整回复 | P95 1.2s | 0% | **PASS** |

Outbox 优化使用 batch=100、publish concurrency=20、poll=20ms。1000 msg/s 单 API 基线为 239.14 msg/s且出现 6 次连接池失败；三 API 分流提升约 72%并将失败归零，证明扩容有效，但不能据此宣称 1000 msg/s 通过。

详细过程见 `report/压测报告.md` 和 `report/压测调试全过程.md`。

## 7. 安全与成本

- `.env` 未被 Git 跟踪；`.env.example` 不含真实密钥。
- 自动测试和容量测试显式覆盖 Mock LLM URL、测试 key 和 model。
- 最终压测隔离库无 LLM usage 新增，本轮真实 DeepSeek 调用、token 和费用新增为 0。
- 多租户越权、财务脱敏、工具 allowlist、高风险二次确认均有自动化测试。
- 默认数据库连接池从每实例 20+20 收敛为 8+4，完整 Compose 理论预算约 60，低于 PostgreSQL 默认 100。

## 8. 尚未通过与后续方案

唯一主要容量缺口是 1000 msg/s 突发。建议在独占 8C16G 环境配置 Ingress/Nginx、3+ API、副本化 worker 与 PgBouncer，保留 Outbox/NATS/数据库连接指标后重跑。必须实际接收接近 30,000 条且无丢失、可在约定时间排空，才能改判通过。

非阻塞工程限制：专用语义 embedding、大规模人工 RAG 盲评、长时间数据库故障与网络分区、批量死信治理尚未作为生产级项目完成。
