# 教育平台 AI 客服服务压测报告

## 1. 结论

2026-09-23 在 macOS arm64 + Colima 的本地 Docker Compose 环境完成了四组可复现压测。稳定流量、突发流量、100 QPS 财务查询和 20% LLM 超时降级均无业务失败。财务查询 P95 为 140 ms，满足题目的 P95 < 500 ms 要求。

本次按“面试项目”规模执行，并非生产容量证明：没有在固定专用环境完整执行 500 WebSocket、200 msg/s 持续 5 分钟和 1000 msg/s 持续 30 秒。

## 2. 环境与口径

| 项目 | 配置 |
| --- | --- |
| 宿主机 | macOS arm64 |
| 容器 | Colima，Docker Compose v2 5.5.1 |
| 工具 | Locust 2.32.6 |
| 服务 | FastAPI + PostgreSQL + Redis + NATS JetStream + Qdrant + worker |
| LLM | 本地 Mock LLM，避免真实 API 费用和网络抖动 |
| 限流 | 压测时临时调高，不让限流器掩盖服务处理能力 |
| 资源上限 | 未单独设置 CPU/内存上限 |

所有场景使用 `scripts.seed_data` 创建的固定租户、用户和会话。HTTP 接入场景每次都生成唯一 `message_id`，避免幂等逻辑把重复请求当成成功吞吐。

| 场景 | 参数 | 原始样本 | 吞吐 | P50 | P95 | P99 | 失败 |

`raw/*_stats.csv` 是 Locust 定时落盘的最后一个完整采样窗口，因此请求数可比终端停机汇总少一个采样周期；延迟、吞吐和失败数据均来自这些保留的 CSV。

## 5. LLM 超时降级

Mock LLM 按请求计数确定性注入故障：每第 5 个请求延迟 5 秒，worker 超时为 2 秒，因此注入比例为 20%。注入逻辑另有单元测试验证 `1..10` 中恰好第 5、10 次触发。

客户端的 69 次完整问答全部收到 `reply.end`，失败率为 0%，证明超时会转换为可用的降级回复，而不是断开 WebSocket。

同时，P50 也上升到约 2.1 秒。这说明当前单 worker/同一消费链路存在队头阻塞：20% 慢 LLM 请求会抬高其他消息的等待时间。如进入生产容量验收，应增加 worker 并发度或实例数，并按租户/会话评估有序性边界。

## 6. 复现

API/worker 需先以压测配置重建，避免测到默认业务限流或消耗真实 DeepSeek 额度：

```bash
DEEPSEEK_API_URL=http://mock-llm:8101/v1/chat/completions \
TENANT_RATE_LIMIT_PER_MINUTE=1000000 \
USER_RATE_LIMIT_PER_MINUTE=1000000 \
docker compose up -d --no-deps --force-recreate api worker scheduler mock-llm

make seed
make loadtest-stable
make loadtest-burst
make loadtest-finance
```

LLM 超时场景另需用 `LLM_TIMEOUT_SECONDS=2` 重建 worker，并通过 `PUT http://localhost:8101/control` 设置 `{"delay_ms":5000,"delay_every":5}`，再执行 `make loadtest-llm-timeout`。

测试后执行 `docker compose up -d --no-deps --force-recreate api worker scheduler mock-llm` 即可恢复 `.env` 配置。本次执行结束后已清零 Mock 故障开关，并恢复 DeepSeek URL、model、key 和 30 秒超时配置。

## 7. 原始证据与局限

- Locust CSV：`report/raw/`
- 场景脚本：`loadtests/locustfile.py`
- Mock 故障注入：`mocks/mock_llm/main.py`
- 可复现命令：`Makefile`
- 测试验证：152 个 unit/integration 通过；Mock LLM 配置下 10 个 E2E 通过。

未完成的生产级证据包括：500 长连接、200 msg/s 持续 5 分钟、1000 msg/s 持续 30 秒、固定容器配额、连续资源曲线和多轮重复试验。因此本报告可作为面试演示与架构验证，不应作为生产 SLA 或容量承诺。
