# 教育平台 AI 客服故障注入报告

## 结论

2026-09-23 已在本地 Docker Compose 环境完成 Redis 中断、NATS 中断和消费者积压恢复三组真实容器故障测试，三组全部通过。机器可读原始证据保存在 [`fault-matrix.json`](fault-matrix.json)。

## 实测结果

| 故障 | 注入方式 | 故障期间观察 | 恢复观察 | 结果 |
| --- | --- | --- | --- | --- |
| Redis 中断 | `docker compose stop redis` | `live=200`，`ready=503`，Redis 标记 error；入站 ACK=202 | Redis 启动后 `ready=200` | 通过 |
| NATS 中断 | `docker compose stop nats` | `ready=503`，2 秒硬超时；入站仍事务持久化并 ACK=202 | NATS 启动后 `ready=200` | 通过 |
| 消费者停止 | `docker compose stop worker` | 12 条消息全部 ACK=202，`im-inbound-worker pending=12` | worker 启动后 pending/ack-pending 均回到 0 | 通过 |

三组测试结束后 consumer 数据均为：

```text
pending=0
ack_pending=0
redelivered=0
```

## 测试中发现并修复的问题

1. NATS 容器停止时，旧 `/health/ready` 会被 NATS 初始连接/DNS 重试拖住，不能及时返回 503。现在使用 `asyncio.timeout` 硬限制为 2 秒，并禁止探针连接重连。
2. Qdrant 搜索异常原本会透传为 HTTP 500。现在 RAG 在向量库故障时 fail-closed，返回固定 `evidence_level=NONE`、空引用和无依据话术，不允许 LLM 自由编造租户事实。

这两个行为均有会先失败的回归测试，修复后通过。

## 复现

```bash
make seed
make faulttest
```

`faulttest` 是显式破坏性本地测试：它会短暂停止 Redis、NATS 和 worker，但会在每个场景以及外层 `finally` 中恢复服务。不要对共享或生产环境执行。
